### 实测结果

路由为 `system`（跟随系统，不等于保证直连）；共记录 70 次请求，全部 HTTP 200，耗时 310–1379ms。

| 操作 | 次数 | 耗时范围 |
| --- | ---: | ---: |
| 配额 | 40 | 365–1255ms |
| 重置次数 | 10 | 345–961ms |
| 每日用量 / 订阅推算 | 10 | 780–1064ms |
| profile Token 统计 | 2 | 370–371ms |
| 工作区名称 | 2 | 310–323ms |
| 重置状态 | 3 | 970–1379ms |
| 其他请求 | 3 | 349–1001ms |

本次没有复现先前的超时，不能据此认定原因为代理、DNS、TLS 或服务端。本轮保留现有 20 秒请求超时、8 秒工作区名称超时及现有路由配置，没有添加自动重试。该样本不代表长期稳定性。

## 5. 何时继续处理重试与连接环境

后续若再次发生超时，先读取白名单诊断行，对同一操作做少量复验，再按证据处理：

| 复现结果 | 后续处理 |
| --- | --- |
| 已确认的系统 / 显式代理配置错误 | 修正现有配置，复验同一接口；不自动绕过用户选择的路由 |
| DNS、TLS、证书故障 | 处理对应环境问题，保持证书校验 |
| 401 | 沿用认证失效与重新登录流程 |
| 403、429、解析错误 | 确认业务限制或响应变更，建立脱敏回归夹具；不立即重复请求 |
| 可复现的短暂超时、断连、502 / 503 / 504 | 再为相应只读 GET 引入有限重试 |

有限重试的候选边界：默认关闭、最多两次、约 1 秒退避、45 秒总截止时间；在原始错误映射前分类，固定同一个代理 context，截止时真正取消 URLSessionTask。取消、明确断网、代理认证、证书及解析错误不重试。OAuth 刷新、登录、切号和有副作用的请求不加入该策略。实施前需补齐尝试次数、截止时间、取消和代理隔离测试。
